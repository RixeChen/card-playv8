# 好友棋牌房 · 在线玩牌网页应用

一个前后端一体的小网站：**打开网址 → 填昵称 → 建房/进房 → 叫朋友输房间号就能一起打牌**。
不需要注册登录，不需要上架应用商店，不需要数据库。

支持四款游戏：**港式五张牌（梭哈）、唬牌（吹牛/骗牌）、保皇、升级（拖拉机）**。

技术栈：Node.js + Express + Socket.IO + 原生 HTML/CSS/JavaScript（**没有编译、没有打包**），
只占一个端口，部署到任何免费云平台都很省事。

## 二、本地运行（3 步）

### 第 1 步：装 Node.js

去 <https://nodejs.org> 下载 **LTS（长期支持版）**，一路下一步装完。
装完打开**新的**终端窗口，输入下面两条命令验证：

```bash
node -v
npm -v
```

能显示出版本号（例如 `v20.11.0` / `10.2.4`）就说明装好了。

> 本项目要求 Node **18 或更高**。如果版本低于 18，请重新下载 LTS 版。

### 第 2 步：安装依赖

在终端里进入项目目录（把路径换成你自己的）：

```bash
cd card-party
npm install
```

看到 `added 89 packages` 之类的提示就成功了，会多出一个 `node_modules` 文件夹。

### 第 3 步：启动

```bash
npm start
```

看到下面的输出就说明跑起来了：

```
==============================================
  好友棋牌房已启动
  本机访问： http://localhost:3000
==============================================
```

浏览器打开 **http://localhost:3000** 就能玩了。
停止服务：在终端按 `Ctrl + C`。

### （可选）跑一遍自检

```bash
npm test
```

会模拟几百局随机对局，检查规则有没有崩溃、计分是否配平。全部 `通过 N 项，失败 0 项` 就正常。
（这一步不需要任何额外依赖，也不需要启动服务。）

另外还有两个「端到端」脚本，会用真实的客户端连服务器跑一遍建房/进房/出牌/重连，
需要先启动服务、并额外装一个测试用依赖：

```bash
npm install socket.io-client --no-save
node scripts/e2e.js        # 唬牌：建房 → 加入 → 出牌 → 质疑 → 掉线重连 → 解散
node scripts/e2e-all.js    # 四款游戏各走一遍
```

## 三、常见问题排查

| 现象 | 原因 / 解决办法 |
|---|---|
| `'node' 不是内部或外部命令` | Node.js 没装好，或装完后没**重开终端**。重启电脑还不行就重装 LTS 版。 |
| `npm install` 卡住 / 很慢 | 换国内镜像：`npm config set registry https://registry.npmmirror.com`，然后再 `npm install`。 |
| `Error: Cannot find module 'express'` | 依赖没装。确认终端当前目录是 `card-party`（里面有 `package.json`），再执行一次 `npm install`。 |
| `EADDRINUSE: address already in use :::3000` | 3000 端口被别的程序占了。换端口启动：<br>Windows：`set PORT=4000 && npm start`<br>Mac/Linux：`PORT=4000 npm start` |
| 页面能打开，但一直显示"等待开始"/没反应 | 打开浏览器按 F12 → Console，看有没有红色报错。最常见是 `/socket.io/socket.io.js` 加载失败，说明部署平台屏蔽了 WebSocket（换 Render / Koyeb / Railway 这类支持 WebSocket 的平台）。 |
| 手机连不上电脑上的服务 | ① 电脑和手机要在**同一个 WiFi**；② 地址不能用 `localhost`，要用电脑的**内网 IP**（Windows 在终端输入 `ipconfig` 找「IPv4 地址」，一般是 `192.168.x.x`）；③ Windows 防火墙可能拦截，临时关闭防火墙或允许 Node.js 通过。 |
| 朋友说点了没反应 / 掉线 | 免费云平台一般会休眠（见第五节）。第一次打开要等 30 秒左右，之后就正常了。 |
| 加入了但提示"牌局进行中" | 本局已经开始，等这局结束（房主点「下一局」）再加入；刷新页面通常能自动回座位。 |
| 五张牌提示"本游戏最多 5 人" | 这是正常的：牌组只保留 8~A 共 28 张，每人 5 张，所以最多 5 人。 |
| 五张牌打完一局就卡住 | 房主需要在结算界面点「**继续游戏**」才会进入下一局；只剩一位有筹码时会自动结束并出现「重新开始」。 |
| 我想清空所有房间 | 重启服务即可。所有房间数据都存在内存里，重启就清空（这是刻意设计，不需要数据库）。 |

## 四、五款游戏规则速查（本实现采用的玩法版本）

更详细的规则说明写在每个 `server/games/*.js` 和 `public/shared/*.js` 的**顶部注释**里，
有歧义的地方都注明了「按哪种通行做法」，想改规则直接改注释旁边那几行即可。

### 1. 港式五张牌（梭哈）· 2–5 人
- **牌组点数只保留 8、9、10、J、Q、K、A（2~7 已剔除）**，共 7 点数 × 4 花色 = **28 张**。
  牌更少 → 下注轮次更少、成牌更快、一局时间更短；代价是 `28 ÷ 每人 5 张 → 最多 5 人`。
- 每家 5 张：**1 张暗牌（底牌）+ 4 张明牌**。
  - ※ 港式五张牌有「末张暗牌（1 暗 + 3 明 + 1 暗）」和「末张明牌（1 暗 + 4 明）」两种通行做法。
    本实现采用后者：这样任何一轮下注时都只有一张暗牌，且每轮都能按明牌牌面决定谁先说话。
- **每发一张明牌后下注一轮，共 4 轮；每一轮的起始位都是「明牌牌面最大」的玩家**
  （从发第 2 张牌起即是如此）。明牌强弱按 四条>三条>两对>一对>散牌，再比单张大小。
- 动作：弃牌 / 让牌 / 跟注 / 加注 / 全下。支持边池（all-in 分层结算），未被跟注的下注会退还。
- 牌型：同花顺 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 散牌。
  因 2~7 已剔除，**A2345 小顺子不可能出现**；最大顺子为 A K Q J 10。
- 完全同点时默认比花色 ♠>♥>♦>♣（可在房间里关掉，关掉则平分）。
  **决定下注先后时也按花色兜底**：明牌牌型完全相同时（例如双方各持一张 A），
  花色大者先说话 —— 否则会退化成按座位先后，"牌面大者先"这条规则就失效了。
- 房间选项：初始筹码、底注、加注单位、每轮加注次数上限、是否比花色。
- **连局机制**：每局结束后点「**继续游戏**」进入下一局，筹码累计；
  当只剩一名玩家还有筹码时**自动结束**，结束界面显示最终排名，房主可点「**重新开始**」重置筹码。

### 2. 唬牌（吹牛 / 骗牌）· 2–8 人
- 一副牌全部发完（可选加 2 张万能王）。持有 **♠A** 的人先喊牌。
- **喊牌**：轮到你时，从手牌扣下**至少 1 张**牌，背面朝下放进本圈，并公布声称的牌型，
  例如「**两张 7**」。喊的张数 = 实际扣下的张数，点数可以撒谎。
- 下家三选一：
  - **质疑**：除喊牌者本人外**任何玩家**都能发起（谁先点谁获得资格）。掀牌后要分两件事看：
    - **收牌**（本圈所有牌归谁）：喊的**假** → 归**喊牌者**；喊的**真** → 归**质疑者**。
    - **出牌权**（接下来由谁喊牌）：交给**判断正确**的一方——喊的假 → **质疑方**；喊的真 → **喊牌者**。
  - **跟牌**：至少跟 1 张。
    - 喊**相同点数** → **张数不限**，可跟任意数量的相同点数牌；
    - 喊**不同点数** → 必须**张数更多**，或**张数相同但点数更大**。
    - 例：上家「两张 7」→ 可跟「一张 7」「三张 7」（同点数，张数不限），
      也可跟「两张 9」（同张数点数更大）或「三张 5」（张数更多）。
  - **放弃**：信任上家并跳过。若除喊牌者外**所有其他玩家都放弃**，本圈累积的牌作为
    **淘汰牌**永久移除、不再翻开；同时**出牌权交给本轮最后一个出牌/跟牌的玩家**，
    由他开启**全新一轮**（牌型基准与比较状态全部重置，可宣布任意合法新牌型）。
- **两人局特殊**：不会把牌全发完 —— 每人只发 `handSize2P` 张（默认 **15**），其余留在暗处不发。
  否则 52 张全发给 2 个人时，双方都能用排除法算出对方手里的每一张牌，吹牛就完全失去意义。
  （3 人及以上仍然全部发完，因为那样无法反推对手手牌。）
- **点数大小**：A > K > Q > J > 10 > … > 4 > 3 > 2 > 小王 > 大王（A 是最大的普通牌，2 最小）。
- **胜负判定**：**率先出完手牌者获胜**，游戏立即结束。
  - 为防止"用最后几张牌吹牛瞬间赢"，出完手牌后会进入一个**质疑确认窗口**
    （默认 15 秒，可调）：窗口内无人质疑才判胜；被质疑且属实 → 质疑者收牌但出完者依然获胜；
    被质疑且是假 → 圈牌归出完者、**出牌权归质疑方**，游戏继续。
- **计分**：输家按**剩余手牌每张牌的点数**扣分，赢家获得全部输家的分数。
  每张牌分值 = 该牌点数（A=14、K=13、…、2=2、小王=15、大王=16）。
- **超时**：30 秒无响应自动代为放弃；该领出时自动出手里最小的 1 张并如实喊出。
- **万能王与喊牌**：开启「加入 2 张王当万能牌」后，王可顶替任意点数。
  喊牌的**牌名与张数完全由真实打出的牌推导**，没有任何写死的默认值：
  有非王牌时喊它们的点数（王去顶替），全是王时才喊「大王 / 小王」。
  例：打出 ♠9 + 大王 → 喊「**两张 9**」；打出 大王 + 小王 → 喊「**两张大王**」。
- 房间选项：无响应自动放弃秒数、出完手牌后的质疑窗口秒数、**两人局每人手牌数**、
  **机器人思考时间（秒）**、是否加 2 张王当万能牌。
- 结束后房主点「**重新开始**」可重置再开一局。

### 3. 保皇（威海保皇）· 固定 5 人
- **4 副牌去掉所有 3、4、5 再去掉 3 张 6，共 165 张**，每人 33 张（无底牌）。
- 8 张大王里随机指定一张为「**皇牌**」，拿到的人即**皇帝**，并由皇帝先出牌。
- 8 张小王里随机指定一张为「**保牌**」，拿到的人即**侍卫**。
  - 皇牌与保牌在同一人手上 = **独保**（1 打 4）。
- **表态阶段**（发牌后、出牌前，默认 20 秒）：
  - 独保 → 皇帝选「明独保 / 暗独保」；否则 → 侍卫选「明保 / 暗保」。
  - **造反**：除皇帝外任何人可点「造反」，满 **2 人**即成功 → 保牌亮出、按明保计分（**得分 ×2**）。
- **牌点**：大王 > 小王 > 2 > A > K > Q > J > 10 > 9 > 8 > 7 > 6。
- **牌型**：只有「糊」（同点数 n 张：一糊=单张、二糊=对子…）。**不能打顺子**。
  - **王挂牌**：大小王可当任意牌混入糊中（如 888+小王 = 四糊 8）。
  - 压牌张数必须相同：**王挂牌 > 糊牌**；否则比主点数，再比挂的大王数、小王数。
  - 例：8888 > 7777；777+小王 > 6666；6666+大王 > 5555+小王；但 **9999 压不了 888+小王**。
- **憋 6**：手里的 6 必须留在**最后一套**出（手里没有 6 则不受限）。
- **过牌可上**：过牌后下一圈还能再出。
- **胜负**：皇帝+侍卫为一方，其余三人为一方；**任何一方全员先出完牌，一局结束**。
- **计分**：侍卫分 = 6 − (皇帝名次 + 侍卫名次)；皇帝分 = 2 × 侍卫分；起义军每人 = −1 × 侍卫分。
  明保或造反成功 → 全员 ×2。独保：明独保头客 +24/其余各 −6，否则 −24/+6；
  暗独保头客 +12/−3、二客 0、三客及以后 −12/+3，暗独保被造反则 ×2。
- 名次：头客、二客、三客、四客（二拉）、五客（大拉）。
- ※ 「踢 / 扭」与「让位（弃皇）」为地方变体，本实现未做，按无踢、无让位计。

### 4. 升级（拖拉机）· 固定 4 人
- **2 副牌 108 张**，对家结队（0/2 号座一队、1/3 号座一队）。
- 每人 25 张，庄家多拿 8 张底牌；庄家先**选主花色**，再**扣回 8 张底牌**（可点「自动扣牌」）。
- 主牌 = 大小王 + 所有级牌 + 主花色全部牌。
- 牌型：单张 / 对子 / 拖拉机（同门相邻的对子，≥2 对）/ 甩牌（同门多张混出，必须压得住人）。
- 跟牌张数必须相同；有该门牌必须先出该门，不够可用主牌「毙」。
- 5=5 分、10=10 分、K=10 分。**闲家得分 ≥80 即上台**。
- 升级表（闲家得分 D）：0→庄家升3级；<40→升2；<80→升1；<120→闲家上台升1；<160→升2；≥160→升3。
- 闲家赢最后一轮 = **抠底**，底牌分 ×2（用主牌抠底 ×4）。级数走到 A 之后再升级即通关。
- 房间选项：起始级数、是否允许甩牌、抠底是否翻倍。

### 5. 德州扑克（Texas Hold'em）· 2–8 人
- 一副 52 张牌，庄家按钮每局轮转；按钮左侧下小盲、第二位下大盲。
- 每人 2 张底牌（仅自己可见），桌面逐街发出 5 张公共牌，用 7 张选最强 5 张比大小。
- 街道推进：翻牌前 → 翻牌 3 张 → 转牌 1 张 → 河牌 1 张 → 摊牌。
- 每轮动作：弃牌 / 过牌 / 跟注 / 加注 / 全下（加注单位为一个大盲）。
- **边池**：有玩家全下时按投入额分层结算，未被跟注的部分退还。
- 只剩一名未弃牌玩家 → 直接收池，无需摊牌。
- 牌型：同花顺 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 散牌（`Poker.bestOf` 从 7 张选 5）。
- 筹码归零即出局；**只剩一名玩家拥有筹码时判定比赛结束，并公布该玩家为获胜者**（赢下全部筹码）。
  若所有人同时输光，同样判定比赛结束（无冠军）。
- **重开规则**：
  - 「下一手」：一手结束后开新的一手，**保留各人筹码**，只轮转盲注位、重洗重发。
  - 「重新开始 / 完整重开」：**任何时候都能发起**（房主特权，牌局进行中也行），
    完整重置所有玩家的筹码、手牌、公共牌、下注池、盲注位置与回合状态，从初始状态干净启动。
- 房间选项：小盲、大盲、每轮最多加注次数、机器人思考时间、**初始筹码**（重开时重置为该值）。
- ※ 未实现：All-in 强制亮牌、Straddle、保险。

## 六之一点五、德州扑克的牌风机器人

德扑的机器人不是"一个 AI"，而是**一桌风格迥异的牌手**。牌风档案集中在
`server/ai/personas.js`，改数值就能调教出新牌风；决策引擎 `strategy.decide()`
按这些参数调制 EV 门槛、加注尺度、诈唬频率与位置敏感度。

| 机器人 | 牌风 | 入池率 | 诈唬 | 下注尺度 | 超池 | 位置敏感 | 范围宽度 | 特点 |
|---|---|---|---|---|---|---|---|---|
| 谭老板 | 稳健价值型 TAG | 18% | 8% | 0.7x 池 | 0% | 0.85 | 0.30 | 挑剔、重位置、少诈唬，强牌做价值下注，懂得放手 |
| yara | 松凶进攻型 LAG | 32% | 24% | 0.85x 池 | 8% | 0.70 | 0.70 | 持续施压，偷盲与半诈唬获利 |
| 布兰妮 | 松弱跟注站 | 46% | 3% | 0.4x 池 | 0% | 0.20 | 0.95 | 什么牌都看、极少加注、弃不掉，抓诈唬也付代价 |
| Tom Dwan | 超激进·超池下注 | 42% | 38% | 1.1x 池 | 35% | 0.80 | 0.85 | 范围极宽、3bet 频繁、overbet 把对手逼进退两难 |
| 石头 | 超紧弱 Nit | 9% | 2% | 0.55x 池 | 0% | 0.90 | 0.10 | 只玩顶级牌，不诈唬；他下大注时通常真有货 |
| 疯子 | 全下狂魔 Maniac | 62% | 50% | 1.3x 池 | 45% | 0.30 | 1.00 | 不看位置不看牌力，高频下注与全下，最大不确定性来源 |

一桌最多 8 人；房主点「🤖 添加机器人」时按入座顺序依次分配这 6 套牌风
（`personas.byIndex()` 循环取），所以一桌 6 个机器人就是 6 种牌风，不会重复。

**参数如何影响决策**（`strategy.js`）：

```
位置因子  posMul     = 1 + positionAware * (位置 - 0.5) * 0.7      // 晚位更松更凶
入池松紧  looseness  = vpip * posMul
EV 门槛   evBias     = (0.28 - looseness) * 底池                   // 松的人门槛低甚至为负
加注尺度  raiseAmt   = max(最小加注, 底池 * betScale)，超池概率 overbet 时 ×1.6
诈唬      bluff      → 小概率把"过牌/跟注"改成加注，或用弱牌漂浮跟一手
全下      allinTendency → 牌不差时直接推
```

界面右侧（牌桌下方）有「桌上机器人的牌风」表，实时显示每个机器人的入池率、
诈唬率、下注尺度和特点；机器人每次行动也会把概率依据写进公共日志，例如：

> 机器人4 思考：【Tom Dwan·超激进 · 超池下注狂人】胜率 34.2%（胜 32.1% / 平 4.2% / 负 63.7%），
> 位置 按钮/晚位，入池倾向 46.8%，底池 120，跟注需 40，底池赔率 25.0%，
> 跟注期望 +9.1（门槛 -21.5）；牌力一般但牌风激进 → 诈唬加注到 132

> 想验证牌风差异：`node scripts/verify-personas.js 60` 会跑 60 局并统计
> 每个牌风的看翻牌率 / 加注数 / 超池数 / 全下数。

## 六之二、机器人（陪练）

人不够时可以让机器人凑桌：

1. 建房后，在**底部房主工具条**点「🤖 添加机器人」，会依次加入「机器人1」「机器人2」……
2. 机器人占真实座位，会**自动出牌**（每步间隔 0.6~1.3 秒，看起来像真人在想）。
3. 想去掉就在顶部玩家条上点那个机器人名字后面的「移除」。
4. 限制：**牌局进行中不能加/减机器人**，需等本局结束；加到本游戏人数上限就加不下了。

机器人策略很朴素（不是 AI 高手）：

| 游戏 | 机器人怎么打 |
|---|---|
| 港式五张牌 | 有一对或更好就加注/跟注，散牌时注额超过 2 倍加注单位就弃牌 |
| 唬牌 | 领出就出最小的牌并如实喊；别人喊牌时 35% 质疑，否则优先跟相同点数，跟不上就放弃 |

**机器人思考时间（唬牌 = 30 秒）**

唬牌里机器人每次出牌前固定等待 **30 秒**（与人类"30 秒无响应自动放弃"的时限一致），
让节奏和真人差不多。这个值集中定义在 `server/games/cheat.js`：

```js
var BOT_THINK_MS = 30000;       // 机器人每次出牌前的等待间隔（毫秒）
var BOT_THINK_JITTER_MS = 0;    // 随机抖动；改成正数（如 2000）可让间隔略有波动
```

也可以在房间里调：设置项「**机器人思考时间（秒）**」（`botThinkSeconds`，默认 30，1~120 可调），
调试时调小就不用干等。

实现要点：

- 机器人延迟**只有一处**代码：`server/rooms.js` 的 `Room.prototype.driveBots`，
  间隔由 `botThinkDelay(game, state)` 统一计算 = `base + Math.random() * jitter`。
- `base` / `jitter` 的默认值是 `DEFAULT_BOT_THINK_MS = 600` / `DEFAULT_BOT_THINK_JITTER_MS = 700`
  （约 0.6~1.3 秒），**游戏模块可用 `botThinkMs` / `botThinkJitterMs` 覆盖**，
  唬牌覆盖了 `botThinkMs` → 30000，其它三款游戏仍走默认快节奏，不会被拖慢。
- 唬牌的「无响应自动放弃」计时器在**轮到机器人时会自动延后到「思考时间 + 5 秒」**，
  避免定时器抢在机器人出牌之前替它自动放弃。
- 想单独验证：先 `npm start`，再 `node scripts/verify-bot-delay.js`，
  会连续测 3 次机器人的出牌间隔（每次约 30 秒）。
| 威海保皇 | 侍卫一律暗保、皇帝独保一律暗独保；其他人 40% 造反；出牌优先打最小的非 6 单张，受憋 6 约束 |
| 升级 | 选主选自己牌最多的花色；扣底用自动；出牌出最小的合法牌 |

想改机器人策略，编辑对应 `server/games/*.js` 里的 `botAct(state)` 函数即可（返回 `{ playerId, action }` 或 `null`）。

## 六之三、AI 决策层（server/ai/）

机器人不靠"写死的如果就"，而是先算概率再算期望值。这一层与具体游戏解耦，
港式五张牌和德州扑克共用同一套代码，以后新的扑克类游戏也能直接接。

```
server/ai/
├── odds.js       # 蒙特卡洛胜率估算
└── strategy.js   # 理性下注决策
```

### odds.js —— 胜率估算

```js
odds.equity({
  mine: [...],              // 我的最终牌（已知部分）
  board: [...],             // 已确定的公共牌
  known: [...],             // 其他已看见但非公共的牌（如五张牌里对手的明牌）
  opponentSlots: [1,1],     // 每位对手还未确定的牌张数（五张牌每人 1 暗；德州每人 2）
  boardSlots: 5,            // 还需补几张公共牌（德州翻牌前=5、河牌后=0）
  deck: [...],              // 完整牌堆（内部自动排除已知牌）
  iterations: 1200,         // 模拟次数
  rng: odds.seeded(42),     // 可注入随机源 → 测试结果可复现
  evaluator: Poker.bestOf,  // 手牌强度函数（五张牌传 scorePartial，因前几轮不足 5 张）
  comparator: Poker.compare
})
// → { win, tie, lose, iterations }
```

多路底池下的口径：**lose** = 任一对手严格更强；**win** = 我严格最强；**tie** = 全员持平。
tie 在 EV 里按半个底池折算。

### strategy.js —— 决策引擎

```js
strategy.decide({ ...同上牌面参数, pot, toCall, myChips, betUnit, maxRaises, aggression })
// → { action, amount, equity, potOdds, evCall, evRaise, reason, valid }
```

核心公式：

```
equityValue = win + tie/2                      // 胜率等值
potOdds     = toCall / (pot + toCall)          // 跟注需达到的最低胜率
EV(跟注)    = equityValue * pot - (1 - equityValue) * toCall
EV(加注)    = equityValue * (pot + bet) - (1 - equityValue) * bet
```

决策树：`EV(跟注) <= 0 且需付筹码 → 弃牌` → `优势足够大且还有加注次数 → 加注` → `否则跟注/过牌`。
`reason` 字段就是机器人写进公共日志的那句"人话"，例如：

> 机器人2 思考：胜率 75.8%（胜 75.8% / 平 0.0% / 负 24.2%），底池 30，跟注需 20，
> 底池赔率 40.0%，跟注期望 +17.9；优势明显（期望 +33.1 > 跟注 +17.9）→ 加注 40

### 边界情况（均有处理）

| 情况 | 处理 |
|---|---|
| 筹码不足以跟满 | 只能 `allin`（EV 为正）或 `fold`，绝不返回无法执行的 `call`/`raise` |
| 平局 | `tie` 单独统计，EV 按 0.5 折算，不会当成全胜 |
| 边池 | 引擎按"当前总底池"近似；分层信息在 `sidePots` 里，可自行细化 |
| 无加注次数 / 零筹码 | 自动降级为跟注、过牌或弃牌 |
| 未知牌不够发 | 返回 `error`，策略保守弃牌，而不是算出荒谬胜率 |
| 前几轮不足 5 张牌 | 传入 `Poker.scorePartial`（2~4 张部分手牌评估器） |

### 在游戏里接一段机器人

在 `server/games/xxx.js` 导出 `botAct(state)`，返回 `{ playerId, action }` 或 `null`：

```js
function botAct(state) {
  var st = state;
  if (!st || st.stage !== 'betting') return null;
  var p = st.players[st.turnIndex];
  if (!p || !p.isBot) return null;
  var d = strategy.decide({ /* 牌面 + 筹码参数 */ });
  if (d.reason) log(st, p.name + ' 思考：' + d.reason);   // 概率依据写进日志
  return { playerId: p.id, action: { type: d.action === 'raise' ? 'raise' : 'call' } };
}
```

思考时间（每次出牌前的等待）由 `rooms.js` 的 `botThinkDelay(game, state)` 统一计算，
游戏模块可用 `botThinkMs` / `botThinkJitterMs` 覆盖。

## 七、以后怎么新增一款游戏

  // 玩家每次操作（出牌/过/选牌…）都走这里

## 八、一些设计上的说明

- **所有规则判定都在服务端**，客户端只负责画界面。有人改前端 JS 也骗不了牌。
- **每个玩家收到的状态是单独裁剪过的**，别人的暗牌根本不会下发到他浏览器（见各游戏的 `view()`）。
- **房间数据存内存**，服务重启就清空；超过 6 小时无活动的房间会自动清理。
